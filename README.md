# Неон Графикс — сайт и админка

Лендинг производителя наружной рекламы и админка для клиента.
Next.js 14 (App Router) + TypeScript + Tailwind, деплой на Vercel из ветки `main`.

## Как это устроено

- Весь текст и все картинки сайта лежат в `data/content.json`.
- Структура файла описана zod-схемой `lib/content-schema.ts` — она же даёт типы
  компонентам и проверяет контент при сборке и перед публикацией.
- Админка на `/admin` правит копию контента в браузере (черновик в localStorage),
  а по кнопке «Опубликовать» коммитит `data/content.json` в GitHub. Vercel видит
  коммит и пересобирает сайт — изменения появляются через 1–2 минуты.
- Каждая публикация — обычный git-коммит, поэтому история и откат встроены.

## Разработка

```bash
npm install
npm run dev
```

Сайт: http://localhost:3000, админка: http://localhost:3000/admin.

Без `GITHUB_TOKEN` админка работает в локальном режиме: публикация и загрузка
картинок пишут файлы прямо на диск (`data/content.json`, `public/images/…`).

Без `ADMIN_LOGIN`/`ADMIN_PASSWORD` в dev-режиме действует вход `admin` / `admin`.

```bash
npm run build   # обязательная проверка перед пушем
npm run lint
```

## Переменные окружения

Локально — `.env.local` (см. `.env.example`), на проде — Vercel → Settings →
Environment Variables (Production + Preview). После изменения переменных нужен
редеплой.

| Переменная | Зачем |
| --- | --- |
| `ADMIN_LOGIN` | Логин админки |
| `ADMIN_PASSWORD` | Пароль админки |
| `SESSION_SECRET` | Подпись сессионной куки, случайная строка ≥32 символов |
| `GITHUB_TOKEN` | Fine-grained токен, Contents: Read and write на этот репозиторий |
| `GITHUB_REPO` | `Puhich/neon-graphics` |
| `GITHUB_BRANCH` | `main` |
| `TELEGRAM_BOT_TOKEN` | Токен бота от @BotFather — заявки |
| `TELEGRAM_CHAT_ID` | Чат или группа, куда падают заявки |
| `SMTP_HOST` / `SMTP_PORT` | `smtp.yandex.ru` / `465` |
| `SMTP_USER` / `SMTP_PASSWORD` | Ящик и пароль приложения (не основной пароль) |
| `SMTP_FROM` / `SMTP_TO` | Отправитель и получатель писем с заявками |

Проверить, что подключено, можно в админке: **Проверка интеграций** — там же
кнопка тестовой заявки.

## Картинки

Оптимизатор Vercel выключен, работает свой лоадер `image-loader.js`: для каждой
фотографии в `public/images` нужны три файла — `name.webp`, `name-640.webp`,
`name-1280.webp`. Загрузка через админку делает этот набор автоматически
(sharp, качество ~78, ширина базы до 1400px), поэтому клиент может грузить
что угодно прямо с телефона.

Ассеты коммитятся в момент загрузки с пометкой `[skip ci]`, чтобы не запускать
лишнюю пересборку: деплой запускает только кнопка «Опубликовать».

## Структура

```
app/
  page.tsx              главная страница
  privacy/              политика конфиденциальности
  not-found.tsx         404
  robots.ts, sitemap.ts генерируются из домена в админке
  admin/                админка (login + группа (panel) с разделами)
  api/admin/…           логин, публикация, загрузка, иконки, статус
  api/lead              приём заявок: Telegram + почта
components/             секции сайта и компоненты админки (components/admin)
lib/                    схема контента, реквизиты, публикация, иконки, env
data/content.json       весь контент сайта
```

## Чего нельзя трогать без веской причины

`components/SectionWatermark.tsx` и блоки `@media (hover: none)` в
`app/globals.css` — там выстраданная логика рыбки-водяного знака: на десктопе
это `fixed` внутри `clip-path` секций, на тач-устройствах рыбка живёт только в
первом экране. Любые «улучшения» ломают рендер в мобильном WebKit.
