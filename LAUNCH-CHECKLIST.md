## 1b. Как выпустить токены

**GitHub (публикация из админки):** github.com → аватар → Settings → в самом низу Developer settings →
Personal access tokens → **Fine-grained tokens** → Generate new token. Repository access: **Only select
repositories** → `neon-graphics`. Permissions → Repository permissions → **Contents: Read and write**
(Metadata: Read появится сама). Значение вида `github_pat_…` показывается один раз — сразу копировать.
Записать дату истечения: когда токен протухнет, публикация начнёт выдавать ошибку.

**Telegram (заявки):** в Telegram найти **@BotFather** → `/newbot` → получить токен вида `8123456789:AAH…`.
Затем узнать chat_id: написать боту (или добавить его в группу и написать там), открыть в браузере
`https://api.telegram.org/bot<ТОКЕН>/getUpdates` и взять `chat.id`. **У группы id с минусом** —
минус копировать обязательно.

**Почта Яндекса (заявки):** id.yandex.ru → Безопасность → включить двухфакторную аутентификацию →
**Пароли приложений** → тип «Почта» → получить 16-символьный пароль (это `SMTP_PASSWORD`, не основной
пароль от почты). В настройках почты должен быть включён доступ по IMAP/SMTP.
Хост `smtp.yandex.ru`, порт `465`, `SMTP_USER` и `SMTP_FROM` — полный адрес ящика.

**Как вбивать в Vercel:** проект → Settings → Environment Variables → Key + Value, отметить окружения
**Production** и **Preview** → Save. Без кавычек, без пробелов по краям. После добавления переменных
нужен редеплой: Deployments → последний деплой → ⋯ → Redeploy.

Проверить результат: админка → **Проверка интеграций** — там статус каждого канала и кнопка тестовой
заявки.

## 10. Переезд с Vercel на свой сервер

Решено: хостим на **VPS Beget** (домен клиента там же). Делается отдельной сессией,
примерно на полдня.

Конфигурация: 1–2 ядра, **2 ГБ RAM** минимум — `next build` вместе с `sharp` на 1 ГБ
падает по нехватке памяти. На сервере сразу включить своп на 2 ГБ, чтобы сборка не
конкурировала с работающим сайтом. Оплату брать помесячно, пока переезд не проверен.
Автопродление включить. Раньше рассматривали Aeza MSKs-1 (≈570 ₽) — по цене то же,
но Beget удобнее клиенту: один кабинет с доменом.

- [ ] Сервер: nginx как reverse proxy на порт 3000, TLS через certbot, приложение под PM2
- [ ] Деплой: GitHub Actions по пушу в `main` → SSH на сервер → `git pull`, `npm ci`, `next build`, `pm2 reload`
- [ ] Перенести все переменные окружения из раздела 1 в `.env` на сервере
- [ ] **Переделать чтение контента на рантайм.** Сейчас `lib/content.ts` делает
      `import raw from "@/data/content.json"` — контент запекается при сборке, и на своём
      сервере каждая правка текста означала бы полную пересборку (1–2 минуты). Нужно читать
      файл через `fs.readFile` с той же валидацией схемой и кэшем. Правка примерно на полчаса
- [ ] **`lib/publisher.ts`: включить обе ветки сразу.** Сейчас запись на диск — это фолбэк
      «нет токена GitHub». На сервере надо писать на диск (сайт обновляется мгновенно)
      **и** коммитить в GitHub (история версий и бэкап). Меняется одно условие
- [ ] Платные бэкапы у хостера можно не брать, если админка исправно коммитит в GitHub —
      тогда репозиторий и есть бэкап контента
- [ ] Переключить DNS на IP сервера, дождаться сертификата, проверить редирект www
- [ ] Обновить README и раздел 1 чек-листа: переменные будут не в Vercel, а в `.env`
- [ ] После переезда правки из админки применяются мгновенно, без ожидания 1–2 минут —
      сказать клиенту (в разделе 9 обещано обратное)

Побочный плюс рантаймового контента: становится легко сделать превью секций прямо
в дашборде админки — без пересборки и без запросов в GitHub за файлами.
